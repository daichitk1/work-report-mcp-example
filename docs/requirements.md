# 要件定義

Work Report MCPは、ChatGPTが**直前の1つのユーザー依頼**に対して行った作業を、確認しやすいレポートとして表示するMCP Appです。会話全体や作業履歴の集計は対象にしません。

## 目的と対象

ユーザーが「何をしたか」「なぜそうしたか」「何を確認したか」「何が残っているか」を短時間で把握し、必要なら次の依頼へ進めることを目的とします。

`1ユーザー依頼 = 1 Work Report` とし、レポートはその依頼と、その依頼のために実際に行われた作業だけを扱います。内部のTool Logや推論の逐語的な記録は表示しません。

## Toolを使う条件

`show_work_report` を使う通常の条件は、次のすべてを満たす場合です。

1. ユーザーから具体的な作業依頼を受けた
2. 調査・判断・変更・確認など、複数の工程を行った
3. その依頼の最終結果を返す段階にある

ユーザーが「今回何をした？」「Work Reportを見せて」のように明示的に求めた場合も使えます。単純な質問、雑談、アイデア相談だけ、途中の進捗報告では原則として使いません。Toolの説明はモデルに選択条件を伝えるもので、発火を保証する仕組みではありません。

## レポートに含める情報

| 項目               | 内容                                                   |
| ------------------ | ------------------------------------------------------ |
| `title`・`summary` | 今回の依頼の結果と、その短い説明                       |
| `completedWork`    | 実際に行った作業と、必要に応じた技術詳細・変更ファイル |
| `decisions`        | AIが行った判断と、その理由                             |
| `verification`     | 確認事項、実施状態、結果                               |
| `remainingWork`    | 検証以外も含めた、残っている作業                       |
| `references`       | 今回実際に参照したURLと、その用途                      |
| `suggestedActions` | 次にChatGPTへ依頼できる操作                            |

`verification.status` は `completed`（実施した）、`not_completed`（未実施）、`unknown`（実施したか不明）を区別します。`completed` は検証を実施したという意味で、成功したという意味ではありません。結果や失敗は別途 `result` で伝えます。

判断・確認と作業の関連は、項目IDと `relatedWorkIds` で表します。未確認の検証と、それ以外の残作業は異なる項目として扱います。情報のない配列は空にし、埋め合わせの情報を生成しません。入力の正確な型と上限は [共通Schema](https://github.com/daichitk1/work-report-mcp-example/blob/main/packages/contracts/src/work-report.ts) を参照してください。

## 情報の正確さ

- 作業の実施と動作の確認を分けて記述します。変更しただけで確認済みとしません。
- AIによる判断は、検証済みの事実と区別して表示します。
- 実施していない作業やテスト、変更していないファイル、参照していないURLを追加しません。
- このアプリはGit diffやテスト結果を自動取得して独立検証しません。レポートは監査証跡ではありません。

## 画面と操作

最初に結果の概要、作業件数と確認状態を示します。作業・判断・確認をたどり、選んだ項目の説明、関連する項目、必要に応じた技術詳細やファイルを確認できます。未確認事項、参考情報、次に依頼できる操作も表示します。

初期表示は平易な日本語を優先し、詳しい技術情報は必要に応じて開けるようにします。モバイルでも項目を選び、詳細を読める構成とします。次の操作はChatGPTへ次のメッセージを送るための候補であり、外部の作業を自動実行しません。

## 接続と安全性

Remote MCP Serverの `/mcp` はOAuth認証を必須とし、Bearer tokenの署名・issuer・audience・有効期限・必要な `work-report:show` scopeを検証します。未認証は401、権限不足は403です。認証設定が不足しても、認証なしで公開しません。

レポートに秘密値や不要な個人情報を含めず、サーバー側でも入力のサイズ・Schema・秘密情報・ファイルパス・参照URLを検査します。高リスクな情報を見つけた場合はレポート全体を拒否し、値をエラーやログに出しません。検出には限界があるため、送信前に秘密値を除くことが必要です。境界の詳細は [Security Boundaries](./security/boundaries.md) を参照してください。

レポート本文はUTF-8 JSONで64 KiB以下とし、HTTPリクエスト本文には別の上限を設けます。各項目の文字数や配列件数にも上限があり、超過分を黙って切り詰めません。

## 対象外

会話全体・セッション全体・一日のまとめ、GitHubやCIからの自動取得、Databaseへのレポート履歴保存、独自LLM、レポートからの作業の自動再実行は対象外です。実環境のAuth0ログインからChatGPT内の画面表示まで確認する方法は [セットアップ](./setup.md) にあります。
